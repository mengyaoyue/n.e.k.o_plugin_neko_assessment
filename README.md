# 心理测评室（neko_assessment）

心理测评 · 人格测评 · 趣味测评，一个面板全包。**一题一屏**、答题时**实时看维度剖面**、
结果可**追踪趋势**、可**复制 / 导出 / 生成分享卡**。
答案与结果**只写在本机 `data/records.json`**，不上传、不联网。

> ⚠️ 全部量表**仅供自我了解与反思，不是医学诊断**，也不能替代心理咨询或治疗。

## 三、内容重做（v1.2.0）

被吐槽「瞎搞」的几条老量表不是换皮，是换题：

- **成人依恋**：原来是一道题选一个类型，算不出两条轴。改成 **12 题 · 焦虑/回避两轴**（5 点），
  四象限由两条轴的百分比判定（≥55% 记为高），并按 ECR 的结构命名，明确标注「自编短筛，不是 ECR 官方计分」。
- **心理韧性**：换成 **CD-RISC-10 原题**（10 条，0-40 分），分级注明「常用参考分档，非官方切点」。
- **社交能量**：单维度拆成 **人群消耗 / 独处充电 / 刺激阈值**（各 8 题，共 24 题），
  电量 = 100 − 消耗。
- **拖延症**：从「一个拖延分」改成 **12 道情境选择题**，区分冲动型 / 回避型 / 卡壳型三种动机，
  三种动机的解法完全不同（改环境 / 降评价压力 / 给默认起点）。
- **情绪智力**：维度改成 Goleman 四分法（自我觉察 / 自我管理 / 社会觉察 / 关系管理），口径写清楚。
- **趣味量表**：题目保留，但每个结果都补了「tagline + 三条行为细节 + 一个可能会踩的坑 + 最搭类型」，
  并各自配了上面那件「物件」；结果一律褒义、具体到行为，不写「可能存在 XX 倾向」这种诊断腔。

## 五、氛围与动效（v1.4.0）

之前是「白卡片 + 白背景」，看久了平。这一版加了三层东西，都只用 CSS/Canvas，无外部库：

- **氛围层**：壁纸上面叠一层彩色纱（multiply），再叠极光（四团缓慢漂移的柔光，只在四周发光、中间留白，
  不会把内容糊成白雾），最上面是网格 + 扫描线 + 漂浮光点。壁纸被压住杂色，白卡片才浮得起来。
- **HUD 感**：卡片有渐变描边、四角取景框、章节编号（`01/02/…` 等宽字体小方块）、
  结果页主视觉的取景框角标、图表外圈的旋转虚线环；顶栏状态条用 mono 小字 + 呼吸绿点。
- **节奏**：
  - 进场错峰（卡片 40–140ms 依次浮起，量表卡按列错开）；
  - 结果页条形从 0 长到目标值（0.85s 曲线过渡），数字（总分/编号）滚动到位；
  - 图表 `pop` 出现，九型轮盘/环图外圈虚线缓慢旋转；
  - 按钮悬停流光扫过，进度条有一道来回的高光；
  - 量表卡跟随鼠标位置打出柔光（`--mx/--my`），分类色做左侧光条。
- **分类色**：人格紫、情绪健康蓝、职业青、关系粉、趣味橙、优势绿——卡片和标签吃同一个 `--cat`。
- **降级**：`prefers-reduced-motion: reduce` 下所有动画/过渡全部关闭，只保留静态层。

## 六、怎么用

1. 在插件管理里 **打开界面**（或在对话框发 `/测评` 看清单）；
2. 选一份量表 → 一题一屏作答（**键盘 1-5 直接选，Enter 下一题，Backspace 回上一题**）；
3. 答题时下方会**实时显示维度剖面**（随你的选择变化）；
4. 结果页：类型卡 + 雷达图（维度 ≤8 时）+ 双极轴 + 分面明细 + 维度条 + 长处/盲点；
   可**复制结果**、**生成分享卡（PNG）**、**再测一次**；
5. 「记录」页看历史与**趋势**；「画像」页看跨量表综合报告。

PHQ-9 第 9 题（自我伤害念头）若有得分，结果页会**优先显示危机求助热线**——请务必先看那一块。


新增量表只需往 `_scales.py`（或新的扩展模块）的 `SCALES` 里加一条：

- **Likert 型**：给 `options` + 条目 `dim`（可选 `facet`、`reverse`）；
- **选择型**：给每项的 `options`（带 `weights`）；
- **官方短筛**：`kind="clinical"` + `bands` + `fixed=true` + `official_count=题数`；
- **分面量表**：给 `facets`（`key/name/dim/desc`），条目带 `facet`；
- **按原始分分级的维度**：给 `dim_bands` 并把 `dim_bands_on` 设为 `"score"`。

计分、面板、双极轴、分面明细会自动支持。

## 十一、默契测试：她本人逐题作答

一轮 10 题，你和 YUI 各答两问（**她自己选什么** + **猜你选什么**），双方都交卷后同时揭晓。
分数扣掉随机基线，所以 **0 分 = 和瞎猜持平**。

答案**不是插件算出来的**，是她在真实对话里自己说的。做法与三条踩过的坑：

1. **一题一条推送**。宿主对单条消息的正文有 token 上限；整卷 10 题（约 700 字符）
   一次推过去会被截断——实测她只拿到第 1、2 题全文和第 3 题的题干（"第三道你选项
   都没写完"）。所以改成一题一条短文、**等她答完再发下一题**，长度由构造保证 ≤150 字符。
2. **不要求她吐 JSON**。让她用自己的话说两个编号（`1 2`、`本喵选1，猜主人2`、
   `选B，猜你A` 都认）；解析不出就算这题没答上，**绝不替她补一个**。
3. **读回顺序：实时总线 → 宿主对话流 → 她的对话库。**
   - **实时总线**（`ctx.bus.memory.get_sync`）是**唯一不滞后**的通道，走内存不走落盘。
   - 后两条都依赖宿主**落盘，而落盘是懒触发的**——要等你发言或空闲维护才快照。
   - 所以还有一步 **「补收她的回答」**：先把没接住的题标成"没答上"，过一会儿回头再收一次；
     收回来的一律标「·补收」，让人看得出是当场接住的还是事后补的。
   - 等待时间每题 25 秒（不是 75 秒）——10 题 × 75 秒 = 12.5 分钟，那是让人以为程序卡死了的时长。
4. **读对话库时按自增 `id` 锚点，不按时间戳**。`time_indexed.db` 是快照式写入，
   同一批新增的多行**共享同一个时间戳**，用 `timestamp > since` 会读到你那条、漏掉她那条。

她没答上的题**不进计分**（面板逐题标"没答上"，`total` 只算她真答上的题数），
面板同时贴出她每题的原话——这是"真的她在答"的唯一证据。
